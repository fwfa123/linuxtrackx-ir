## Feature Plan 0002: Correctness & Hardening for MFC42 Installation Flow

### Context
Follow-up to `0001_PLAN.md` and `0001_REVIEW.md`. The implementation added alternative sources and fixed the missing `mfc42.dll` symlink. This plan addresses remaining correctness gaps, UI mismatches, and hardening items so both `mfc42.dll` and `mfc42u.dll` are consistently installed and discoverable across all paths.

### Final Goals
- Ensure both `mfc42.dll` and `mfc42u.dll` are copied to `~/.config/linuxtrack/tir_firmware/` in every successful extraction path.
- Ensure UI flows reference Visual C++ 6.0 installers (VS6SP6 / VC6RedistSetup) and validate accordingly.
- Verify downloaded installer integrity via SHA256 before extraction.
- Make copying idempotent (safe overwrite) and clean up temp resources.
- Keep direct DLL download disabled unless explicitly enabled with strong warnings.

### Files to Modify
- `src/qt_gui/extractor.cpp`
- `src/qt_gui/extractor.h` (add small helpers)
- `src/qt_gui/sources_mfc42.txt` (minor comment notes only, if desired)

### Technical Changes

#### 1) Copy both DLLs in all success paths (Critical)
- Add a helper to centralize copy logic and reduce duplication:
  - `bool copyDllsToFirmware(const QStringList &sourceCandidates, const QStringList &dllNames)`
    - For each `dllName` in `dllNames` (both `mfc42.dll`, `mfc42u.dll`):
      - Iterate candidate paths; on first existence, ensure firmware dir exists, remove existing destination if present, then `QFile::copy` to `~/.config/linuxtrack/tir_firmware/<dllName>`.
      - Log success/failure per file; return true if at least one copy succeeds, but do attempt both.
- Apply this helper in these code paths:
  - `Mfc42uWinetricksExtractor::wineFinished()` success flow (stage handling after Wine extraction).
  - `Mfc42uWinetricksExtractor::cabextractFinished()` success flow.
  - `Mfc42uWinetricksExtractor::tryWinetricksInstall()` after mfc scans (replace single-file copy with dual-file copy).
  - `Mfc42uWinetricksExtractor::browseDirPressed()` direct file case (check for both `mfc42u.dll` and `mfc42.dll`).
  - Keep existing VS6SP6 path (already copies both) but route through helper for consistency.

Implementation details:
- Candidate paths to check should include both `system32` and `syswow64` as used today, plus the prefix root (e.g., `/drive_c/mfc42*.dll`).
- Destination overwrite: if `QFile::exists(dstPath)`, call `QFile::remove(dstPath)` prior to `QFile::copy` and log.

#### 2) VC6RedistSetup extraction must yield both DLLs
- `extractFromVC6RedistSetup()` currently defers the copying to `wineFinished()` which only places `mfc42u.dll`.
- Ensure that the post-extraction copy logic (see 1) attempts both DLLs when VC6RedistSetup is used (same source candidates as winetricks flow).

#### 3) UI text and validation for VC6 installers
- In `on_BrowseInstaller_pressed()` (MFC42 flow):
  - Change prompt to: “Select Visual C++ 6.0 Redistributable installer (VS6SP6.EXE or VC6RedistSetup*.exe or vcredist.exe)”.
  - Validation: accept filenames containing `VS6SP6`, `VC6RedistSetup` (any locale suffix), or `vcredist` (case-insensitive). Remove/replace messaging that mentions “Visual C++ 2015-2022”.

#### 4) SHA256 integrity verification before extraction
- In `downloadVCRedist()`:
  - Parse SHA256 (already present in `sources_mfc42.txt` entries).
  - After download, compute SHA256 via `QCryptographicHash::Sha256`.
  - If checksum is present and does not match, log a clear error, delete the downloaded file, and continue to next source.
  - Only commence extraction on match or if no checksum provided.

#### 5) Cleanup of temporary prefixes and directories
- Winetricks temp prefix and any temp extraction dirs should be removed on success/finalization when safe:
  - After copies complete, attempt `QDir(tempPrefix).removeRecursively()` (guard for emptiness/in-use). Log but ignore failures.
  - VS6SP6 temp dir is already removed; keep consistent cleanup patterns elsewhere.

#### 6) Messaging polish
- Ensure progress messages consistently state the active method:
  - “Installing via winetricks mfc42”, “Extracting from VS6SP6.EXE”, “Extracting from VC6RedistSetup_deu.exe”, “Copying mfc42/mfc42u to firmware…”.
- On partial success (only one of the DLLs found), show a warning that both are recommended, but proceed if at least `mfc42u.dll` exists (depending on runtime needs), and suggest installing the missing one.

#### 7) Direct DLL download remains disabled by default
- Keep `downloadDirectDLL()` returning false with visible warning.
- Optionally: gate enabling behind a compile-time macro or an advanced setting; if enabled, require checksum field and show explicit security warning before proceeding.

### Test Plan
- Fresh Arch Linux environment (wow64 only, no wine32):
  - Winetricks path: Verify that after success the firmware dir contains both DLLs.
  - VS6SP6 path: Confirm both DLLs present; verify temp dir cleanup.
  - VC6RedistSetup path: Confirm both DLLs present; verify temp prefix cleanup.
  - Browse directory with extracted files: If directory contains one or both DLLs, ensure both are copied appropriately.
- Negative/edge cases:
  - Destination files pre-exist: verify overwrite works and logs are clear.
  - SHA256 mismatch for a source: verify skip and fallback to next source.
  - No DLLs found after a purportedly successful method: clear error and guidance.
- Winebridge installer: confirm both symlinks are created by `check_data.exe` (already implemented in 0001) and point to the files in `tir_firmware`.

### Acceptance Criteria
- All extraction methods that succeed result in both files present in `~/.config/linuxtrack/tir_firmware/` (when available from source), with idempotent behavior.
- UI text and validation correctly reference VC6 installers; no mentions of VC++ 2015–2022 in this flow.
- Downloaded installers verified by SHA256 when provided.
- Temporary resources removed where safe after completion.
- Logs clearly indicate chosen method, outcomes for both DLLs, and any fallbacks.
