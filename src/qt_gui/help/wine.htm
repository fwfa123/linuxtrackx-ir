Linuxtrack X-IR - Wine Support

To allow Windows programs running under Wine to use headtracking, Linuxtrack X-IR installs a Wine bridge (NPClient.dll and related PE files) into each Wine or Proton prefix where you need tracking. The bridge channels headtracking data to TrackIR-enabled applications and FreeTrack-compatible applications. TrackIR firmware with companion files must be available on the Linux host (even if you are not using TrackIR hardware for tracking).

Install TrackIR firmware and mfc42u.dll first using the prerequisites on the Gaming tab of ltr_gui.

Then use Install Wine Bridge (Lutris, Steam Proton, or custom Wine prefix). The GUI copies bridge files from /opt/lib/linuxtrack/wine_bridge/, writes registry keys with wine reg, and links firmware DLLs into the prefix.

You can also install from the shell: scripts/install/install_wine_bridge.sh <WINEPREFIX> <wine-binary>

Install the bridge into every wine bottle/prefix where you require headtracking.

Modern Installation Methods

LinuxTrack X-IR now uses modern installation methods for better compatibility with current distributions:

Method 1: Winetricks Installation (Recommended for Debian/Ubuntu/MX)

The most reliable approach for Debian-based systems is to use winetricks: WINEPREFIX=~/.wine winetricks mfc42

Method 2: Package Manager Installation (Other Distributions)

Some distributions have mfc42 packages available:
  • Fedora/RHEL/CentOS: sudo dnf install mfc42
  • Arch Linux/Manjaro: sudo pacman -S mfc42
  • OpenSUSE: sudo zypper install mfc42

Note: Ubuntu/Debian/MX Linux do not have MFC42 packages in their repositories and should use winetricks instead.

Method 3: Manual Installation

As a last resort, manually copy mfc42u.dll from a Windows system to the LinuxTrack firmware directory.

The installation process will automatically try these methods in order, providing clear guidance if manual intervention is required.

Modern MinGW Build System

LinuxTrack X-IR uses MinGW-w64 cross-compilation for generating real Windows PE binaries for Wine/Proton compatibility.

Benefits of MinGW Approach

  • Real Windows Artifacts: outputs are .exe and .dll PE binaries
  • WOW64-friendly: aligned with modern Wine 11.0+ runtime model
  • Cleaner Host Dependencies: no winegcc-specific compile path required
  • Native Linux Symlink Handling: filesystem link creation stays on the Linux side
  • Simplified CI/CD: consistent MinGW toolchain behavior across distros

Built Components

The build system generates the following Wine-compatible components:
  • NPClient.dll - TrackIR API compatibility (32-bit)
  • NPClient64.dll - TrackIR API compatibility (64-bit)
  • FreeTrackClient.dll - FreeTrack API compatibility
  • Controller.exe - Hotkey control utility
  • Tester.exe - TrackIR testing utility
  • Tester64.exe - 64-bit TrackIR testing utility
  • ftc.exe - FreeTrack testing utility
  • TrackIR.exe - Fake TrackIR executable for games

Programs in the Wine prefix

After you install the Wine bridge into a bottle/prefix, several programs are available there:

Controller allows you to bind hotkeys to pause/resume and recenter the tracking. It can be minimized to the tray so it doesn't clutter the desktop. When a Controller is started, window pops up and you should specify the pause key and recenter key - just press the appropriate button followed by key/keys of your choice (max 2 keys). One thing to be aware of is, that the Controller works (meaning it sees the hotkey pressed) only inside the bottle/prefix where you installed it!

TrackIR is a fake TrackIR executable, that is required by certain games in order to accept the tracking data. It also loads TIRViews library, that channels the headtracking data into following games:

  • Battlefield 2
  • Wings of War
  • Nascar Racing Season 2003
  • Collin McRae Rally 04
  • ToCA Race Driver 2
  • Richard Burns Rally
  • F1 Challenge
  • MSFS 2004, FSX
  • CFS3
  • Prepar3D

FreeTrackTester, Tester (and on 64bit Wine also Tester64) allow you to troubleshoot the Linuxtrack-Wine installation. They are FreeTrack and TrackIR client applications and if they are working, the installation is OK.

To remove the bridge, delete the Linuxtrack folder under Program Files or Program Files (x86) in that prefix, and remove registry keys under NaturalPoint, Freetrack, and HKLM\SOFTWARE\Linuxtrack.

Note on profiles

When the game/application is started for the first time, a new profile is created automatically by copying the default one. When adjusting the tracking in the ltr_gui, be sure to select the correct profile first, otherwise you won't see any change (because you are modifying the wrong profile).

The TrackIR software uses the plus/minus 500mm as a displacement limit, so to use the full displacement range, set the limits for translations accordingly (go to the Tracking Setup pane, select the appropriate profile, then press the Detailed Axes Setup button and for translations set limit to 500).

Troubleshooting

If you encounter issues with the Wine installation:

Common Issues

  • Build Errors: Ensure MinGW toolchains are installed and on PATH
  • Payload not found: Confirm /opt/lib/linuxtrack/wine_bridge/NPClient.dll exists after cmake --install
  • Artifact Mismatch: expected outputs are .exe/.dll (not .exe.so/.dll.so)
  • Missing Files: Verify all dependencies are installed (see README for details)

Verification Steps

1. Check that MinGW toolchains are available: which i686-w64-mingw32-gcc x86_64-w64-mingw32-gcc 2. Test the build process: cmake -S . -B build && cmake --build build -j$(nproc) 4. Check generated files: look for .exe and .dll files in wine bridge build directories
